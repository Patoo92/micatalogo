=== A3 — stripe-success.php: activar plan desde metadata + idempotencia (ALTO) ===
Archivo: stripe-success.php (59 líneas). Problemas actuales:
  - NO actualiza tiendas.plan (el plan lo setea el webhook, pero la página de
    retorno debería activarlo YA, no esperar al webhook).
  - $tienda_id cae a GET (línea 11: ?tienda_id=) si falta metadata: IDOR. Validar
    contra $_SESSION['tienda_id'] cuando exista sesión.
  - INSERT de factura sin idempotencia: una recarga doble duplica facturas.
Solución (de NOTAS 3):
  $plan = in_array($session->metadata->plan ?? '', ['starter','pro','business','enterprise'])
            ? $session->metadata->plan : 'pro';
  $stmt = $pdo->prepare("UPDATE tiendas SET stripe_customer_id = ?, stripe_subscription_id = ?,
                         plan = ?, trial_ends_at = NULL WHERE id = ?");
  // factura idempotente: columna stripe_referencia VARCHAR(100) UNIQUE
  INSERT INTO facturas (...) SELECT ... WHERE NOT EXISTS
  (SELECT 1 FROM facturas WHERE stripe_referencia = ?)
  Migración SQL necesaria (migrations/011_stripe_referencia.sql):
  ALTER TABLE facturas ADD COLUMN stripe_referencia VARCHAR(100) NULL
    AFTER metodo_pago, ADD UNIQUE KEY uq_stripe_ref (stripe_referencia);

4) QUÉ HOSTING ES IDEAL PARA ESTE PROYECTO (2026)
================================================================================

REQUISITOS MÍNIMOS DEL PROYECTO:
- PHP 8.2+ (ideal 8.3) con extensiones: pdo_mysql, gd (con WebP para
  thumbnails), mbstring, curl, openssl, fileinfo, intl (opcional).
- MySQL 8 / MariaDB 10.6+.
- Apache con mod_rewrite (o Nginx con rewrite equivalente) y soporte .htaccess.
- Variables de entorno reales (el código las prefiere sobre .env).
- Cron (para el backup A8). WHM/cPanel o acceso SSH.
- HTTPS/SSL gratis (Let's Encrypt) y posibilidad de registrar dominios extra
  (plan Business ofrece dominio personalizado).
- SMTP saliente 587 (Brevo).

RECOMENDACIÓN SEGÚN TU PERFIL:

A) VPS (recomendado para este proyecto por ser SaaS multi-tenant con Stripe
   webhook, cron y dominios personalizados):
   - HETZNER CLOUD CX22 (2 vCPU / 4 GB RAM / 40 GB NVMe) ~4,5-5 €/mes:
     MEJOR RELACIÓN PRECIO/RENDIMIENTO en Europa. Ubuntu 24.04 + Apache +
     PHP 8.3-FPM + MariaDB + Certbot. Total control: cron, .env real, SSL,
     múltiples dominios. Requiere saber administrar Linux.
   - DIGITALOCEAN Droplet Premium ($7-12/mes, 1-2 vCPU, 1-2 GB RAM, NVMe):
     ecosistema y documentación excelentes, facturación por segundo (2026),
     sin data centers en LATAM.
   - VULTR High Frequency (~$6/mes): red de data centers enorme, incluye
     São Paulo y Santiago (mejor latencia para LATAM).
   - IONOS / OVHcloud / Contabo: alternativas económicas europeas.

B) Hosting COMPARTIDO gestionado (si NO quieres administrar un servidor):
   - HOSTINGER (plans Premium/Cloud desde ~$3-4/mes): PHP 8.3, MySQL, hPanel
     con SSH y cron, datacenter en São Paulo. El más fácil para no técnicos.
     OJO: precios promocionales y renovación 3-5x; compromiso de 24-48 meses.
   - CLOUDWAYS (desde ~$11/mes): capa administrada sobre DigitalOcean/Vultr.
     Buen punto medio: te evitas el mantenimiento del SO sin perder control.

C) PARA EVITAR: hosting compartido ultra-económico sin cron ni SSH (bloquea
   webhooks de Stripe, backups A8 y .env reales). No sirve para este proyecto.

RECOMENDACIÓN CONCRETA (si pudiera elegir yo):
  → HETZNER CLOUD CX22 (Ubuntu 24.04) + Apache/PHP-FPM 8.3 + MariaDB + Certbot
    + cron de backup cifrado (A8). Costo ~5 €/mes.
  → SI PREFIERES NO ADMINISTRAR SERVIDOR: Hostinger Cloud o Cloudways, con la
    misma stack.
  → Data center: elegir el más cercano a TU audiencia (Europa o São Paulo).
